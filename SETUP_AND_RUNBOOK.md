# AI-Powered Multi-Agent Data Pipeline Orchestrator

## Public Setup and End-to-End Runbook

This guide is written for a fresh local installation. It deliberately uses no developer-specific paths, tokens, workspace URLs, or run IDs.

The API orchestrates the following LangGraph workflow:

```text
Ingest -> Bronze -> Validate -> Silver -> Gold -> Report -> AI Data Quality Report
```

The local application is a FastAPI service. Bronze, Silver, and Gold are submitted to Databricks job IDs configured in `app/databricks/jobs.py`. The AI report is generated by a local Ollama model.

## 1. What You Need

### Required for API startup and local validation

- Python 3.12 recommended; another Python version may work if all dependencies support it.
- This repository.
- The dependencies in `requirements.txt`.

### Required for the full pipeline

- A Databricks workspace.
- Permission to run and inspect the three configured Databricks jobs.
- A valid Databricks host URL and personal access token, or another supported SDK authentication method.
- Ollama with the `llama3.2` model.
- A CSV file readable by the local Python process.

## 2. Get the Repository

Clone the repository or open the existing checkout, then change to its root directory:

```powershell
cd "<path-to>\AI-Powered-Multi-Agent-Data-Pipeline-Orchestrator"
```

The commands in this document must be run from the repository root unless stated otherwise. The root should contain:

```text
README.md
requirements.txt
app\
data\raw\sales.csv
```

## 3. Create an Isolated Python Environment

An isolated environment prevents this project from changing packages used by other projects.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks activation, either allow local scripts for your user or invoke the environment's interpreter directly:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

Then activate again. Alternatively:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Using `python -m ...` ensures that packages and commands use the selected interpreter. A global installation with `--user` is also possible, but a virtual environment is the more reproducible public setup.

## 4. Configure Databricks

Create `.env` in the repository root. This file is ignored by Git and must never be committed:

```env
DATABRICKS_HOST=https://<your-workspace-host>
DATABRICKS_TOKEN=<your-personal-access-token>
```

Use the workspace host supplied by Databricks. Do not include angle brackets in the real values. Do not paste credentials into issues, chat, screenshots, source files, or logs.

The current code uses the numeric job IDs in `app/databricks/jobs.py`:

```text
BRONZE_JOB_ID = 913826646441028
SILVER_JOB_ID = 734858437358560
GOLD_JOB_ID = 747976443992049
```

These IDs are workspace-specific. A different user must replace them with job IDs from their own workspace, or provision equivalent jobs. The jobs must be compatible with the expected Bronze, Silver, and Gold stages.

### Important data-location limitation

The API accepts `source_file`, and the local Ingest and Validator agents read that path. However, the current Databricks calls use only `job_id`; they do not pass `source_file` or `pipeline_id` as job parameters. Therefore, Databricks must already be configured to read the intended data independently. A local Windows path is not automatically uploaded or made available to Databricks.

### Test Databricks authentication

From the repository root:

```powershell
python -m app.databricks.test_connection
```

The direct script form is also supported:

```powershell
python app\databricks\test_connection.py
```

Expected output includes:

```text
Databricks Connection Successful
```

This test checks workspace authentication only; it does not run the Bronze, Silver, or Gold jobs.

## 5. Install and Start Ollama

Install Ollama using the official installer. On Windows, Windows Package Manager can be used:

```powershell
winget install --id Ollama.Ollama --exact --source winget --accept-source-agreements --accept-package-agreements
```

Restart the VS Code terminal after installation so it receives the updated PATH. Verify the command:

```powershell
ollama --version
```

Download the model configured in `app/config/config.json`:

```powershell
ollama pull llama3.2
ollama list
```

The list should contain `llama3.2:latest`.

Start Ollama in a dedicated terminal and leave it running:

```powershell
ollama serve
```

The local Ollama API is normally available at `http://127.0.0.1:11434`.

If Windows reports that `ollama` is not recognized, restart the terminal. If needed, add Ollama's installation directory to the user PATH. A common per-user location is:

```text
C:\Users\<username>\AppData\Local\Programs\Ollama
```

As a temporary workaround, run the executable by its full path:

```powershell
& "C:\Users\<username>\AppData\Local\Programs\Ollama\ollama.exe" serve
```

## 6. Start the FastAPI Service

Open a second terminal, activate `.venv` if it was created, and run:

```powershell

python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Expected startup output includes:

```text
Uvicorn running on http://127.0.0.1:8000

```

If port `8000` is occupied, use another port consistently:

```powershell
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8001
```

Keep this terminal running.

## 8. Run the Included Clean Demo

The repository includes `data/raw/sales.csv`, a five-row CSV with these columns:

```text
order_id,customer_id,product,amount
```

In Swagger, open `POST /run-pipeline`, select **Try it out**, and submit:

```json
{
  "pipeline_id": "DEMO_001",
  "source_file": "data/raw/sales.csv",
  "source_type": "csv"
}
```

The equivalent PowerShell request is:

```powershell
$body = @{
    pipeline_id = "DEMO_001"
    source_file = "data/raw/sales.csv"
    source_type = "csv"
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/run-pipeline" `
    -Method POST `
    -ContentType "application/json" `
    -Body $body
```

The endpoint is synchronous. It waits while each Databricks job is polled, so the request can take several minutes.

For a clean run, HTTP `200` should return a response shaped like this. Run IDs, timestamps, file hashes, and AI wording vary:

```json
{
  "pipeline_id": "DEMO_001",
  "source_file": "data/raw/sales.csv",
  "source_type": "csv",
  "pipeline_status": "SUCCESS",
  "ingest_status": "SUCCESS",
  "validation_status": "SUCCESS",
  "transform_status": "SUCCESS",
  "report_status": "SUCCESS",
  "bronze_run_id": "<run-id>",
  "bronze_status": "RunResultState.SUCCESS",
  "silver_run_id": "<run-id>",
  "silver_status": "RunResultState.SUCCESS",
  "gold_run_id": "<run-id>",
  "gold_status": "RunResultState.SUCCESS",
  "retry_count": 0,
  "row_count": 5,
  "file_hash": "<sha256-hash>",
  "execution_start": "<utc-timestamp>",
  "execution_end": "<utc-timestamp>",
  "ai_summary": "<model-generated summary>",
  "severity": "Low",
  "business_impact": "<model-generated impact>",
```

For the quality-test datasets, `validation_status` is expected to be `FAILED` and `errors` should contain the issues detected by the Validator Agent. Because the current graph does not stop after validation failure, Databricks stages may still run; do not interpret successful Databricks statuses as proof that validation passed.

## 11. CSV Support and Current Validation Contract

The local code reads CSVs with `pandas.read_csv()` using default options. In practice, the reliable input contract is:

- Comma-delimited CSV.
- A header row.
- A file path readable from the API process.
- Standard quoting and escaping accepted by pandas.
- Values that pandas can parse with its default encoding and type inference.

Extra columns are accepted by the local pandas reader. The application does not enforce required columns or a complete schema. `source_type` is stored but is not currently used to select a parser, so the implementation is effectively CSV-only.

The Validator Agent currently checks:

- Empty dataframes after a successful read.
- Exact duplicate rows.
- Null cells.
- A lowercase `age` column for values below `0` or above `120`.

It does not currently provide explicit validation for delimiters, encoding, dates, emails, phone numbers, amounts, quantities, Boolean values, required columns, or file-size limits. Very large files are read into memory by pandas and may require substantial RAM.

## 12. Databricks and Ollama Notes

- The three Databricks calls are blocking and poll until the job reaches `TERMINATED`.
- The current polling code has no application-level timeout.
- The Databricks job IDs are not portable between workspaces.
- The local source path is not passed to Databricks as a job parameter.
- Ollama must be running when the graph reaches the AI report node.
- The Ollama client requests JSON output, and the AI agent also handles common fenced JSON responses.
- The API currently exposes no authentication, authorization, rate limiting, or upload endpoint. Keep it bound to localhost for local demonstrations.

## 13. Troubleshooting

### `uvicorn` is not recognized

Uvicorn is either not installed in the selected environment or its script directory is not on PATH. Install requirements and use:

```powershell
python -m uvicorn app.main:app --reload
```

### `ModuleNotFoundError: No module named 'fastapi'`, `langgraph`, or another dependency

The package is missing from the interpreter running the command. Activate the intended virtual environment and install:

```powershell
python -m pip install -r requirements.txt
```

Confirm the selected interpreter:

```powershell
python -c "import sys; print(sys.executable)"
```

### `ModuleNotFoundError: No module named 'databricks'`

Install the declared SDK dependency:

```powershell
python -m pip install databricks-sdk
```

It is included in the repository's `requirements.txt`.

### `default auth: cannot configure default credentials`

The Databricks SDK cannot find usable credentials. Check the root `.env`, variable names, host URL, token validity, and token permissions. Do not print the token. The client is created lazily so API startup and `/health` do not require an immediate Databricks call.

### `ModuleNotFoundError: No module named 'app'` when running the connection test

Run from the repository root using:

```powershell
python -m app.databricks.test_connection
```

The direct script command is also supported:

```powershell
python app\databricks\test_connection.py
```

### `ollama` is not recognized

Restart the terminal after Ollama installation so PATH is refreshed. If needed, add Ollama's installation directory to the user PATH or invoke `ollama.exe` by its full path as described in Section 5.

### `AI JSON Parse Error`

Make sure `ollama serve` is running and `ollama list` contains `llama3.2:latest`. The project requests JSON output from Ollama and strips common markdown fences. If the model still returns malformed JSON, inspect the response and model availability.

### `GET /favicon.ico 404 Not Found`

Browsers request a favicon automatically. The project does not define one; this does not affect the API or pipeline.

### The pipeline reports success even though validation failed

This is a current workflow limitation. The graph continues to later nodes after validation errors, and the Reporter Agent primarily bases its result on Databricks statuses. Inspect `validation_status` and `errors` instead of relying only on `pipeline_status` until validation short-circuiting is implemented.

### A Databricks job never finishes

Check the job in the Databricks workspace. The current polling loop has no timeout and waits for a terminal state. Stop the local API process with `Ctrl+C` if necessary.

## 14. Security and Public Repository Checklist

Before pushing or publishing the repository:

- Confirm `.env` is ignored and is not tracked by Git.
- Revoke any Databricks token that has been exposed and create a replacement.
- Do not place real host URLs, tokens, run IDs, or personal paths in documentation.
- Use placeholders in examples.
- Use a least-privilege Databricks identity.
- Keep the API and Ollama bound to localhost for local demos.
- Review generated datasets for sensitive information before committing them.
- Consider adding dependency version pins and automated tests before production use.
